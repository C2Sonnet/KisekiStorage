# GitHub公開前の確認チェックリスト

これは公開担当者用の確認表です。**このZIPの作成だけで、全ての権利処理・実機テストが完了したわけではありません。**

## 公開前に必須

- [ ] 著作権者の正式名称を確定し、必要に応じて`NOTICE.md`の表記を更新した
- [ ] `assets/`の人物アバター・アイコン・企業ロゴの再配布許諾を確認した
- [ ] 許可のない画像を差し替え、同梱素材に不足するクレジットを追加した
- [ ] 第三者ライブラリのライセンス条件を確認した
- [ ] CC BY-NC-ND 4.0が**プログラム本体**に適切か最終判断した（CCはソフトウェアへの適用を非推奨）
- [ ] ビルド後の`Cargo.lock`を追加して依存関係を固定した
- [ ] Windows 10/11で `cargo build --release` と `cargo test` を確認した
- [ ] `cargo clippy --all-targets -- -D warnings`を実行し、警告を確認した
- [ ] v1.1.0で導入したZen Maru Gothicが日本語・英語ともに正しく表示されることを確認した
- [ ] フォントOFL全文が配布物に含まれることを確認した
- [ ] セキュリティレビュー（docs/SECURITY_REVIEW.md）に残る確認事項を見直した
- [ ] パーティション表示、ワンクリック、管理者権限、ボタン動作を実機検証した
- [ ] README、ライセンス、CHANGELOGの名称・版番号に矛盾がないことを確認した
- [ ] テスト用の画面写真にユーザー名・デバイス名・私的情報が映っていないことを確認した

## GitHubの初回設定

- リポジトリ名の例：`Kiseki-Storage`
- 説明文の例：`Kiseki Storage（キセキの倉庫）— Windows向けストレージダッシュボード。`
- About欄のTopics例：`rust`、`windows`、`storage`、`dashboard`、`egui`
- まずはソースコードとして公開。実行ファイルの配布はWindows実機検証・依存ライセンス確認後に実施

## リリースノートの書き方

1. `Cargo.toml`とWindowsマニフェストのバージョンを合わせる。
2. `CHANGELOG.md`に更新項目と互換性の注意を追記する。
3. Windowsで生成した実行ファイルの動作と署名状態を確認する。
4. GitHub Releasesに公開する場合は、ZIPやexeの内容・ハッシュ・対応OS・管理者権限要求を記載する。
